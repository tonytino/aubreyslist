- `[manual]` Listing detail page: replaced `SafetyLegend` (a prop-free "key" that always rendered all four `SafetySignal` states regardless of the listing) with `SafetyBadges`, which renders a badge ONLY for the signals that actually apply — the headline celiac-safe/gluten-friendly/stale state (when attested) plus the recent-incident badge (when one exists) — and renders nothing when neither applies. Owner feedback: the always-on four-chip row read as status badges, so a celiac-safe listing showing a "Needs update"/"Recent incident" chip alongside its real status was misleading. Each badge keeps its colour + icon + text-label contract and supplementary tooltip. (Superseded within this release: the standalone `SafetyBadges` row is itself retired and this applicable-signals-only behaviour now lives in `SafetySummary`'s hero badge row — see the "stopped showing the headline safety state twice" entry.)
